Repository field guide · benchmark suite and current changes

From experiment matrix to model comparison

Commit 5d49e7e763c19811e262b51176510311e9470099 connects several MIDI embedding backends to a shared benchmark and reporting path. Current worktree changes add BEAT piano inference and replace CLaMP3's Aria-submodule dependency with local symbolic inference. This companion explains execution boundaries, outputs and evidence limits; the linked CodeTour remains the source navigator.

Architecture and data boundaries

The CLI dispatches backend × experiment pairs. Shared row preparation and feature routing feed either the regression-axis runner or a separate sentiment pipeline. Encoders are independent adapters; model code, pretrained weights and caches cross different external/persistence boundaries. The current worktree adds BEAT and standalone CLaMP3 source beyond the committed adapter set.

Observed persistence boundaries: per-query embeddings under cache/embeddings/, backend-specific experiment runs under outputs/, and comparison snapshots under outputs/model_comparison/. The cache does not encode checkpoint hashes, so code alone cannot establish that two cached matrices use identical model state.

1. Selection and shared dispatch

scripts/run_embedding_benchmark.py loops over backend/experiment pairs, with a separate call for sentiment. The runner resolves explicit/environment/config backend precedence; the shared router maps to a registered encoder. `FEATURE_BACKENDS` also includes Musif, but the CLI defaults to embedding backends. Invalid names fail before feature extraction; a cache hit bypasses model inference.

2. Row preparation and BEAT preprocessing

prepare_rows_and_midi() preserves row/path alignment while filtering failed inputs. It resolves MIDI, converts MusicXML/Kern or generates pitch MIDI, then normalizes non-meta events to channel 0/program 0. The current BEAT adapter passes MIDI through official conversion, a temporary NPZ and PianoTokenizer. Only the upstream “largest tick of” error triggers a lower-PPQ temporary MIDI retry: absolute event ticks are rounded into new delta times, preserving the source file while reducing timing precision. Other errors propagate; later token encoding checks nonempty output.

3. Lazy loader and external runtime

The adapter has module-level references for the model, tokenizer, converter, config, NPZ saver and device. A warm call reuses these references. A cold call checks the BEAT checkout files, imports upstream components, verifies the configured piano checkpoint, and calls the official inference loader. The device default is CUDA when available, otherwise CPU; an explicit BEAT_DEVICE overrides that choice.

4. Windowed inference and validation

The token sequence must start with BOS and have a positive configured context. Each non-overlapping chunk is forwarded independently under inference mode. Content positions are defined by absolute token index (at least 3) and exclusion of EOS/PAD; each chunk’s final-layer mean is weighted by its valid content count. A final dimensionality or finiteness failure is raised before the shared cache can persist it.

5. Adapter representations and pooling

Each registered adapter transforms MIDI differently before the shared cache sees a vector. Adversarial-MidiBERT quantizes note/metadata events into eight-field Octuples; MIDI-GPT parses score/bar windows and normalizes unsupported time signatures; local CLaMP3 converts MIDI to MTF then 64-character patches; BEAT delegates to its piano converter and tokenizer. Their outputs are not interchangeable by construction.

6. Regression and sentiment analysis paths

The axis runner saves the feature matrix and retained rows, searches configured pipelines with seeded KFold/Spearman, selects the smallest anchor count within a score tolerance, then writes out-of-fold predictions and metrics. Sentiment does not enter this search branch: it runs its own CV regression and thresholds out-of-fold predictions for balanced classification summaries.

7. Complete-run comparison reports

The report CLI reads existing backend-specific runs; it does not re-encode MIDI or rerun experiments. The generator chooses the latest matching config/metrics directory, extracts Spearman for axes or required accuracy metrics for sentiment, refuses if any requested experiment/backend pair is missing or malformed, and stages TSV/PNG outputs before atomically renaming the completed report directory.

Interpretation and evidence limits

Observed implementation: Five embedding backends share matrix validation, but their tokenization, model loading and pooling conventions differ. Current tests assert selected deterministic mechanics with fakes; they are software-boundary checks, not evaluations of pretrained models.
Not established: The source and tests do not establish that vectors from different backends are directly comparable, that benchmark scores represent musical similarity, or that the preprocessing is invariant to rendering choices. No real-checkpoint benchmark was run as part of this tour.

Axis metrics depend on target, retained rows, group labels, fold construction and search grid. Sentiment metrics are post-hoc threshold metrics over out-of-fold regression predictions. Report completeness means requested artifacts exist and satisfy expected columns; it does not establish statistical power or scientific validity. The BEAT retry depends on an upstream error-string match and trades PPQ precision for a bounded tick count. CLaMP3's strict load checks tensor-key compatibility but not checkpoint provenance beyond the configured repository/file.
